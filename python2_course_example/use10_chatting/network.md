# 소켓 통신을 이용한 채팅 애플리케이션 동작 방식 (TCP/IP 4계층 기반)

채팅 애플리케이션은 네트워크를 통해 메시지를 주고받기 위해 소켓 통신을 사용합니다. 이 과정은 TCP/IP 4계층 모델을 기반으로 설명할 수 있습니다.

## 1. 계층 모델 개요

TCP/IP 4계층 모델은 네트워크 통신 과정을 단순화하여 설명하기 위한 추상화 모델입니다. 각 계층은 특정 기능을 담당하며, 상위 계층은 하위 계층의 기능을 이용하여 서비스를 제공합니다.

- **애플리케이션 계층 (Application Layer):** 사용자에게 서비스를 제공하는 계층입니다. 채팅 애플리케이션, 웹 브라우저, 이메일 클라이언트 등이 이 계층에 속합니다.
- **전송 계층 (Transport Layer):** 애플리케이션 간의 신뢰성 있는 데이터 전송을 담당합니다. TCP, UDP 프로토콜이 이 계층에 속합니다. 채팅 애플리케이션에서는 일반적으로 TCP를 사용하여 안정적인 연결을 보장합니다.
- **인터넷 계층 (Internet Layer):** 네트워크를 통해 패킷을 전송하는 역할을 합니다. IP 프로토콜이 이 계층에 속하며, 패킷의 주소 지정 및 라우팅을 담당합니다.
- **링크 계층 (Link Layer):** 물리적인 네트워크 매체를 통해 데이터를 전송하는 역할을 합니다. 이더넷, Wi-Fi 등이 이 계층에 속합니다.

## 2. 채팅 애플리케이션의 소켓 통신 과정

1.  **애플리케이션 계층:**
    - 채팅 애플리케이션은 사용자가 입력한 메시지를 전송하기 위해 소켓 API를 호출합니다.
    - 소켓 API는 운영체제가 제공하는 네트워크 통신 인터페이스입니다.
2.  **전송 계층 (TCP):**
    - TCP 프로토콜은 애플리케이션 계층에서 받은 데이터를 패킷으로 분할하고, 각 패킷에 순서 번호를 부여합니다.
    - TCP는 연결 지향적인 프로토콜이므로, 먼저 서버와 클라이언트 간에 연결을 설정합니다 (3-way handshake).
    - 데이터 전송 후에도 연결을 **계속 유지**합니다. 연결 종료는 클라이언트나 서버가 명시적으로 요청할 때 4-way handshake를 통해 이루어집니다.
    - TCP는 신뢰성 있는 데이터 전송을 보장하기 위해 ACK (Acknowledgement) 메커니즘을 사용합니다. 수신자는 정상적으로 패킷을 수신하면 ACK를 발신자에게 전송합니다.
    - 패킷 손실이 발생하면, TCP는 타임아웃 후 해당 패킷을 재전송합니다.
3.  **인터넷 계층 (IP):**
    - IP 프로토콜은 TCP 패킷을 IP 패킷으로 캡슐화하고, 목적지 IP 주소를 IP 패킷 헤더에 추가합니다.
    - IP 패킷은 네트워크를 통해 라우터를 거쳐 목적지 호스트로 전송됩니다.
    - 라우터는 IP 패킷의 목적지 IP 주소를 기반으로 최적의 경로를 선택합니다.
4.  **링크 계층:**
    - 링크 계층은 IP 패킷을 프레임으로 캡슐화하고, 물리적인 네트워크 매체를 통해 전송합니다.
    - 이더넷, Wi-Fi 등의 프로토콜이 사용됩니다.

## 3. 예시: 클라이언트에서 서버로 메시지 전송

1.  클라이언트 애플리케이션은 "Hello, Server!"라는 메시지를 소켓 API를 통해 전송합니다.
2.  TCP는 이 메시지를 여러 개의 패킷으로 분할하고, 각 패킷에 순서 번호를 부여합니다.
3.  IP는 각 TCP 패킷을 IP 패킷으로 캡슐화하고, 서버의 IP 주소를 IP 패킷 헤더에 추가합니다.
4.  링크 계층은 IP 패킷을 프레임으로 캡슐화하고, 네트워크를 통해 전송합니다.
5.  서버는 프레임을 수신하고, IP 패킷과 TCP 패킷을 역캡슐화하여 메시지를 복원합니다.
6.  서버 애플리케이션은 복원된 메시지 "Hello, Server!"를 처리합니다.

## 4. HTTP Stateless 와의 관계

HTTP는 stateless 프로토콜로, 각 요청이 독립적이며 서버는 클라이언트의 이전 요청을 기억하지 않습니다. 이는 HTTP가 TCP 연결을 매 요청마다 맺고 끊는 방식으로 동작하기 때문입니다 (HTTP/1.0). HTTP/1.1에서는 Keep-Alive 옵션을 통해 TCP 연결을 재사용하여 성능을 향상시켰지만, 여전히 각 요청은 독립적입니다.

반면, 채팅 애플리케이션은 클라이언트와 서버 간의 지속적인 연결을 유지하며 실시간으로 데이터를 주고받습니다. 이러한 특성 때문에 소켓 통신은 stateful하다고 볼 수 있습니다. 즉, 서버는 클라이언트와의 연결 상태를 유지하고, 이전 요청에 대한 정보를 기억합니다. 따라서 TCP 연결을 계속 유지하는 소켓 통신이 채팅 애플리케이션에 더 적합합니다.

## 5. 결론

소켓 통신을 이용한 채팅 애플리케이션은 TCP/IP 4계층 모델을 기반으로 동작합니다. 각 계층은 특정 기능을 담당하며, 상위 계층은 하위 계층의 기능을 이용하여 서비스를 제공합니다. TCP 프로토콜은 신뢰성 있는 데이터 전송을 보장하며, IP 프로토콜은 패킷의 주소 지정 및 라우팅을 담당합니다.
