네, 앞서 작성한 코드 예시를 바탕으로 절차지향과 객체지향 프로그래밍을 비교하는 표를 작성해 드립니다.

## 절차지향 vs 객체지향 프로그래밍 비교 (학교 예시 기반)

| 구분 (Category)          | 절차지향 프로그래밍 (Procedural Programming)                                                                            | 객체지향 프로그래밍 (Object-Oriented Programming)                                                                                                              |
| :----------------------- | :---------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **기본 단위 / 중심**     | 함수 (Function) / 정해진 절차 (Procedure)                                                                               | 객체 (Object) / 객체의 속성(데이터)과 행동(메서드)                                                                                                             |
| **데이터와 기능의 관계** | 분리됨 (데이터는 별도로 존재, 함수가 이를 가져다 사용)                                                                  | 결합됨 (객체 내부에 데이터와 관련 기능이 함께 묶임 - **캡슐화**)                                                                                               |
| **코드 구조**            | 기능(함수) 중심의 순차적 구성                                                                                           | 역할(객체) 중심의 상호작용 구성                                                                                                                                |
| **데이터 처리 방식**     | 함수가 데이터를 직접 조작 (예: 전역 `students_db` 리스트 직접 수정)                                                     | 객체에게 요청(메서드 호출)하면 객체가 자신의 데이터를 스스로 처리 (예: `student.add_score()`)                                                                  |
| **상태 관리**            | 전역 변수나 함수의 인자/반환값을 통해 상태 공유 및 관리                                                                 | 객체가 자신의 상태(속성값)를 스스로 관리                                                                                                                       |
| **주요 관심사**          | "무엇을" / "어떤 순서로" 처리할 것인가? (처리 과정)                                                                     | "누가" / "어떤 역할과 책임"을 가지는가? (객체의 역할과 상호작용)                                                                                               |
| **학교 예시 코드 기준**  | - `students_db` (전역 데이터)<br>- `register_student()`, `assign_score()` (독립 함수)<br>- 메인 코드에서 함수 순차 호출 | - `Student`, `School` (클래스)<br>- `my_school`, `new_student` (객체)<br>- `my_school.register_student()`, `student.add_score()` (메서드 호출을 통한 상호작용) |
| **변경 및 확장**         | 데이터 구조 변경 시 관련된 모든 함수 수정 필요 가능성 높음                                                              | 관련된 객체 내부만 수정하면 영향 최소화 가능 (유지보수 용이)                                                                                                   |
| **재사용성**             | 함수 단위 재사용은 가능하나, 데이터 구조 의존성 높음                                                                    | 클래스(설계도)를 통해 객체를 쉽게 재사용 및 확장 가능 (상속, 다형성 등 활용)                                                                                   |
| **복잡도 관리**          | 프로그램 규모가 커지면 데이터와 함수 간의 관계가 복잡해지고 관리 어려움                                                 | 복잡한 문제를 역할별 객체로 나누어 관리 용이                                                                                                                   |

이 표는 두 패러다임의 핵심적인 차이를 보여줍니다. 간단한 작업에는 절차지향이 더 직관적일 수 있지만, 프로그램의 규모가 커지고 복잡해질수록 객체지향의 캡슐화, 재사용성, 유지보수 용이성 등의 장점이 부각됩니다.
